# Salesforce Metadata Agent POC

## Problem statement
Salesforce teams often struggle to answer questions like:
- Which objects and fields are related to a given business process?
- Which metadata components are impacted by a change?
- How do custom objects connect to standard objects and workflows?
- Which documentation or schema definitions explain a relationship or dependency?

This creates operational risk during change management, onboarding, and support. Teams often rely on scattered metadata exports, docs, and tribal knowledge, which makes it difficult to reason across the system quickly and accurately.

## Use case
This proof of concept demonstrates a metadata intelligence assistant for Salesforce that combines:
- GenAI reasoning for natural-language Q&A
- Agent orchestration for planning and validation
- A knowledge graph in Neo4j to model relationships between objects, fields, and business concepts
- Retrieval-augmented generation (RAG) to ground answers in documentation and metadata definitions

The system helps a user ask questions such as:
- "Show me the relationship between Opportunity, Case, and Account."
- "Which fields are connected to the account lifecycle in Salesforce?"
- "What metadata is relevant to our customer onboarding process?"

The answer is generated by combining structured graph knowledge with unstructured docs and metadata context.

## Solution overview
The project is designed as a small AI agent stack:

1. Ingestion layer
   - Reads Salesforce metadata and business docs
   - Normalizes them into structured and document-based sources

2. Knowledge graph layer
   - Stores objects, fields, and relationships in Neo4j
   - Enables graph traversal for dependency and relationship questions

3. Retrieval layer
   - Extracts relevant docs and metadata chunks using vector search and graph context

4. Agent layer
   - Planner decides which tools to use
   - Graph agent answers relationship questions
   - RAG agent answers documentation-style questions
   - Validator checks consistency before returning the final answer

5. GenAI orchestration
   - Generates natural, grounded responses using LLM reasoning over graph + document context

## Core architecture

### 1. Graph-first reasoning
The Neo4j knowledge graph captures metadata relationships such as:
- object-to-object relationships
- field dependencies
- lookup and master-detail links
- domain concepts mapped to Salesforce metadata

This is useful when a user asks "what is connected to Account?" without requiring full metadata export analysis each time.

### 2. Document-grounded generation
The RAG layer loads policy docs, metadata explanations, and process docs so the answer is context-aware and not based only on raw metadata.

### 3. Agent coordination
The planner and supervisor route the request to the correct agent:
- graph question => graph agent
- doc lookup => RAG agent
- validation => validator

This allows the system to answer both structured and unstructured questions in one interaction.

## Example user flow

```text
User: "How is Opportunity related to Account and Case?"

1. Planner identifies this as a metadata relationship question.
2. Graph agent queries Neo4j for nodes and relationships.
3. RAG agent retrieves supporting docs if needed.
4. Validator checks the answer for consistency.
5. LLM returns a concise explanation with metadata references.
```

## Setup

1. Create a virtual environment
2. Install dependencies
3. Configure Neo4j connection settings in .env
4. Run the app or main entrypoint

Example environment variables:

```env
NEO4J_URI=neo4j+s://xxxxxxxx.databases.neo4j.io
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=your_actual_password
```
